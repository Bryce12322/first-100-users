# first-100-users

**给已上线的独立产品，找到下一步值得尝试的最小获客行动。**

输入产品网址和当前阶段，让 Agent 理解产品、核实机会、推荐一条具体行动，并准备执行素材。你授权后，再按可用工具和平台规则协助执行、核对结果。

这是一个以中文编写的 Agent Skill，不是独立应用。名字代表服务的阶段，**不保证带来 100 个用户**。

## 先看它会交付什么

- 一个人群、一个场景，以及为什么优先验证它。
- 一条有证据的获客行动：具体入口、素材、成本、完成标准和观察窗口。
- 区分“候选渠道”“已核实机会”和“目前无法执行”。
- 经授权执行时，记录真实回执；跟进时区分兴趣、安装、有效使用和再次使用。

[看一个公开产品分析示例](examples/tabspace-analysis.md) · [参加首次试用](docs/TRYOUT.md) · [反馈问题](../../issues)

## 适合谁

你已经有可以体验的插件、工具、SaaS 或其他独立产品，正在判断：

- “下一步去哪里找愿意尝试的人？”
- “有访问却没人使用，是渠道问题还是体验门槛？”
- “已经拿到反馈，这一轮该继续什么、停止什么？”

不适合没有产品时挑创业方向、保证流量、批量群发、代刷评价或只要一段广告文案。

## 安装

### 从 GitHub 安装

在你希望安装技能的项目目录执行：

```bash
npx skills add Bryce12322/first-100-users --skill first-100-users -a codex
```

需要 Node.js 和 npm。当前 Skills CLI 上游要求 Node.js 22.20 或更高版本，安装前可用 `node --version` 检查。[上游说明](https://github.com/vercel-labs/skills)

默认安装到当前项目；需要其他客户端时，在安装器中选择对应客户端。CLI 支持的客户端不等于本技能已在这些环境完成行为测试，具体见[验证记录](docs/VALIDATION.md)。

不使用 CLI 时，可将完整的 `skills/first-100-users/` 文件夹复制到所用客户端支持的技能目录。保留其中的 `references/`、`agents/` 和许可证文件；安装后在客户端确认技能可见，再开始试用。

### 下载后，本地安装

下载并解压本仓库，将路径替换为解压后的仓库根目录；不要指向某一个 `SKILL.md` 文件：

```bash
npx skills add "/path/to/first-100-users-release" --skill first-100-users -a codex
```

首次安装可能需要下载第三方 CLI，并访问 npm、GitHub 等服务。客户端、模型、搜索及平台服务的额度或费用由对应服务决定。

CLI 的来源格式和参数见[官方安装说明](https://github.com/vercel-labs/skills/blob/main/docs/commands.md)。

## 第一次怎么用

安装后，在支持技能的 Agent 中明确调用：

```text
使用 $first-100-users 分析我的产品：https://你的产品网址
产品当前阶段：已上线，可公开体验。
已有使用反馈：填写你知道的情况；没有记录的项写未知。
目标受众和语言：中文独立开发者。
本轮预算：不新增现金支出。
我的可用时间：一小时。
只推荐下一轮一个最小获客行动，并准备素材，不发布、不联系别人。
```

不必先填一整份问卷。一个产品网址加上你已知的阶段信息就能开始；如果缺少会改变建议的关键事实，Agent 应只补问必要问题。

已有反馈时，把数字或匿名原话一起提供，避免每一轮都从“重新找测试者”开始。

## 工具与能力边界

| 你希望做什么 | 运行环境需要什么 | 缺少时应怎样处理 |
|---|---|---|
| 理解产品、准备行动卡 | 能读取你提供的资料 | 官网不可读时说明证据缺口，基于已提供资料准备草稿 |
| 核实当前机会和规则 | 搜索、网页读取或获准的连接器 | 不编造帖子和规则，把候选入口与已核实机会分开 |
| 发布、评论或定向邀请 | 明确授权、正确账号、平台允许的工具及费用条件 | 交付草稿和接手步骤，不声称已发送 |
| 持续跟进 | 可用的真实调度工具和获准读取的记录 | 只设计跟进方案，不口头承诺后台运行 |

技能不附带账号、搜索服务、Cookie、API key 或付费额度，也不要求绑定某个特定搜索插件。它不能绕过平台限制；外部页面、规则和报价应在行动时重新核实。

首次试用可以只做分析，不必连接社交账号。产品资料会由你选择的模型和工具处理，请自行选择可以分享的材料。

## 如何反馈

欢迎报告“安装失败”“输出太泛”“问得太多”或“建议不值得做”。无需好评，也不要求 Star。

最有帮助的四项信息：客户端及版本、输入的大意、卡住的位置、是否实际采取了某个行动。不要公开凭据、私密浏览记录、客户名单或完整私密对话。

在仓库 [Issues](../../issues) 选择“试用反馈”或“安装或运行问题”。还没公开仓库时，可直接将反馈交给维护者；详见[试用任务](docs/TRYOUT.md)。
