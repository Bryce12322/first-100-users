# 第一次试用：用你的产品跑一轮

适合已经有可体验产品、愿意判断一条获客行动是否值得做的人。首轮目标是最多 5 位场景匹配的试用者、至少 3 份具体反馈；这是招募目标，不是已达成数据。

准备时间预计 10–15 分钟，实际运行时间取决于模型、联网和资料量。技能按 [MIT](../LICENSE) 开源；使用模型或外部工具可能消耗你自己的额度。不必购买服务、连接社交账号或真的发帖才能提供反馈。

## 做一个任务

1. 按 [README](../README.md) 安装，在客户端确认可以找到 first-100-users。
2. 提供一个可分享的产品网址、你已知的使用情况和本轮时间预算。
3. 要求推荐一条未来 48 小时内值得尝试的最小行动，并准备素材。第一轮只分析，不发布、不联系别人。
4. 判断这条行动是否值得做。如果你后来决定执行，自行操作或另行授权；是否执行都欢迎反馈。

可直接使用：

```text
使用 $first-100-users 分析我的产品：[网址]
当前阶段和已有反馈：[已知事实；未知项写未知]
目标受众：[你最想服务的人]
本轮可投入时间：[例如一小时]
本轮不新增现金支出。
推荐一个未来48小时内值得尝试的最小获客行动，准备所需素材。
只做分析，不发布、不联系别人、不创建定时任务。
```

如果环境无法联网，可以附上官网文案和已有反馈。Agent 应明确这时不能核实实时机会与规则，不应编造链接或声称完成了调研。

## 反馈四件事就够

- **环境与卡点：**用什么客户端和版本？安装或调用在哪一步卡住？
- **建议的价值：**哪条建议让你愿意尝试？没有也请直说。
- **实际行动：**后来做了什么，或为什么没做？结果还没发生就写“尚未观察”。
- **与直接问 AI 比：**多了什么帮助，增加了什么负担？不必另跑一次对照才能提交反馈。

仓库公开后，在 [Issues](../../../issues) 选择“试用反馈”或“安装或运行问题”。只给产品类型和输入摘要也可以，不要求提交完整对话；如果不愿公开，就只描述非敏感问题。

无需 Star、评分或正面评价。不同意联系跟进的人不应收到催促；允许跟进的人可在首次反馈中注明愿意接受一次后续询问。

## 怎样判断这轮有没有价值

维护者分别记录：安装成功、完成行动卡、实际采取行动、愿意再次使用。熟人试用和自然用户分开统计，分母缺失不计算转化率。

首轮在第 7 天复盘：安装卡住就先修安装；建议仍然太泛就先修技能；已采取行动且愿意再用，再考虑扩大推广。
