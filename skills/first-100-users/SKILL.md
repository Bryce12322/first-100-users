# 首批用户获客执行

把“我该怎么推广”变成一次有证据、能执行、可复盘的小行动。目标是首批有效用户，不保证用户数，不用发帖数替代增长结果。

## 入口与参考路由

按当前请求进入，不强制重做已完成阶段：

- 只有产品资料：完成产品理解、机会筛选和行动卡；需要推进实际执行时再询问。
- 已批准动作或明确要求直接执行：复用上下文，核实条件后完成授权范围内的动作，不重复索取相同许可。
- 要求跟进：先查台账和原始回执，不默认新增推广。
- 要求定时运行：确认范围并调用真实调度工具；没有工具就说明未创建。
- 只要求设计：不发布、不联系别人、不创建自动化。

按需读取，不一次加载所有渠道：

- 人群、方法和优先级：[growth-methods.md](references/growth-methods.md)。
- 入口、机会与平台门槛：[channel-cards.md](references/channel-cards.md)。
- 对外发送、发布、修改页面前：[execution-and-verification.md](references/execution-and-verification.md)。
- 保存状态、复盘与定时任务：[measurement-and-followup.md](references/measurement-and-followup.md)。

## 1. 建立最小产品判断

先利用用户提供的官网、商店、文档、反馈和明确授权访问的仓库。只读与定位、使用流程和限制有关的资料，不为营销扫描密钥、客户数据库或整个私有仓库；不把私有代码和用户数据发给第三方获客渠道。

提取足以决策的信息：

- 产品和体验入口；核心能力与不能解决的需求。
- 一个具体用户、一个使用场景、当前替代方法。
- 安装、注册、首次获得价值的步骤；价格、免费限制、权限与隐私边界。
- 上线阶段、已有反馈和推广结果；没有数据则标记未知。
- 已有渠道、目标地区/语言、时间与现金约束。

关键判断标注“已核实 / 用户提供 / 假设 / 未知”，附来源与日期。代码实现不等于线上开放，宣传描述不等于实测成功。不自行安装、购买或修改产品来补证据。

只问会改变本轮决策的缺失信息，优先合并为一到三个短问题。阶段、已有使用反馈等信息会改变首选动作时，先利用已提供资料；必要时尽早询问。答案未到时可以准备条件化草稿，但不把依赖该答案的建议写成定案。数据未知不等于没有真实用户或反馈。

预算未知时按不新增现金支出规划；不能假定邀请、接口、素材生成或 API 调用免费。按用户语言沟通，按目标受众语言起草。

## 2. 选择本轮验证目标

用证据判断瓶颈，不默认缺曝光：

| 当前证据 | 优先验证 |
|---|---|
| 没有真实使用反馈 | 谁愿意尝试，是否理解用途 |
| 有访问却少有安装或注册 | 定位、信任与转化路径 |
| 安装后没有核心操作 | 首次使用障碍 |
| 已有人持续获得价值 | 哪种获客方法可重复 |

聚焦一个人群和场景，写出排除需求。只检查直接阻碍本次动作的承接问题；改站、改代码或埋点作为独立建议，不擅自扩大范围。

## 3. 找方法，再找真实机会

按产品、受众、阶段和约束选择方法，再核实具体讨论、联系人或发布入口。认真评估用户点名的渠道，但不假定适用或可自动执行。

先过四个硬门槛：人群匹配、需求匹配、当前规则允许、账号/工具/预算可执行。再比较需求强度、反馈速度、时间成本、可观测性与账号风险。解释排序，不伪造转化率、流量预测或精确评分。

通常推荐一个首选动作与一个备选；用户要求广泛研究时再扩展。区分潜在渠道和已核实机会。读不到原文或不能核实规则时，不编造链接、帖子、账号、报价或求助内容。

社区参与先读原文和已有回复，确认问题仍存在。只有关键词相同、问题已解决、竞品发布、过时讨论或禁止推广，不是销售机会。先给有用建议；只有产品匹配且规则允许时才披露关联、分享产品。必要时不贴链接，或完全跳过。

## 4. 输出最小行动卡

研究、筛选、素材准备尽可能先完成，让用户只做一次小决策：

先给首选动作和决定它的关键证据，再给行动卡及必要素材。通常保留一个首选、一个备选；不要为了展示研究过程，堆出与本轮选择无关的渠道或长报告。

```text
动作 / 优先级：
目标用户与具体需求：
为什么现在做 / 为什么暂不做其他方式：
具体位置：真实链接、对象与上下文；未核实则明确标注
已准备的内容与步骤：
账号 / 现金成本 / 用户和 Agent 的时间：
希望验证的一个问题：
完成标准 / 结果观察窗口：
阻碍、风险与停止条件：
执行方式：可代执行 / 需用户接手 / 当前不可执行
```

用户只要求分析或设计时，交付建议与素材即可，不把执行确认作为必经步骤。需要推进对外动作但尚未获授权时，再问：“要我执行这条、修改内容，还是换一个动作？”已有明确许可则推进对应范围，不把普通执行拆成重复确认。授权未覆盖的费用、账号、敏感数据、公开承诺或新增范围仍需处理。

## 5. 执行并验证

先读执行参考，使用环境已有且符合平台规则的连接器、API、CLI 或浏览器。Skill 不提供账号、接口权限、付费额度或后台能力；不擅自安装工具或导出凭据。

核实账号、对象、规则、授权和重复状态。先登记待执行动作，再产生副作用。结果不明确时先核查，不盲目重发。

保持真实身份和功能边界，不假装用户、编造体验、买评分、交换投票或群发模板。不承诺不存在的优惠、功能、隐私保护或免费额度。

交付实际内容、链接和平台回执，必要时附截图。区分草稿、已提交、当前账号可见、已确认公开、被过滤、待审核、收到反馈和已确认有效使用。工具成功不等于结果成功。

遇到门槛时完成不受影响的工作，说明具体阻碍，给一个更小的替代动作。没有合适机会就报告零条合格机会，不凑数量。

## 6. 复盘与跟进

按跟进参考保存产品档案与执行记录，包含去重标识、授权范围、回执、失败和反馈。用户资料不进入公共 Skill 包；不能持久化时说明限制，交付恢复摘要。

汇报“做了什么 → 验证到什么 → 尚不知道什么 → 下一步”。发布和点赞不是安装，安装不是有效使用。指标未知不补数，不默认添加追踪代码。

一轮有实质进展的执行结束后，若用户没有拒绝或已配置等价任务，简短询问是否设计定时跟进。默认检查已有实验的新回复、状态和体验问题，准备建议，不自动新增推广或回复。设计与创建分开，用户要求创建后才调用调度工具。

根据反馈决定继续、调整或停止；不要因为每天运行就每天重复发布。
