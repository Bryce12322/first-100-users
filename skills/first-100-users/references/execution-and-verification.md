# 执行、授权与回执

## 能力预检

只发现本轮需要的工具。优先已有专用连接器或官方 API，再用符合平台当前规则的 CLI 或浏览器。遵循环境的专门 skill、工具文档和审批，不猜命令、接口或隐藏应用状态。

分别确认能读、能写、当前身份、平台许可和费用。可搜索不等于可发布，能发布不等于可自动回复，回合结束不等于存在后台服务。

## 授权范围

将明确许可记录为简短约定：

```text
产品与实验：
账号 / 渠道 / 受众或具体对象：
允许动作及数量或时间边界：
内容与产品声明边界：
费用上限 / 私密数据披露范围：
有效期 / 一次性或持续有效：
授权来源 / 仍需确认的变化：
```

同等范围的直接授权不重复确认。分析请求不隐含发布；执行行动卡只覆盖该动作；每天跟进不等于每天发帖。内容、账号、受众、费用、承诺或敏感披露实质变化时重新处理授权。

本 Skill 不覆盖环境对安装、建号、验证码、协议、付款、敏感数据和文件访问等动作的审批/接管要求。不要求把 cookie、密码、API key 放进公开材料或台账。

## 发送前

- 账号是用户已确认用于本任务的身份，不能只因已登录就采用。
- 目的地真实，原文和最新回复已读，需求仍存在。
- 回应有独立价值，产品匹配且关联披露。
- 名称、功能、定价、额度、兼容性、隐私表达有证据。
- 平台和社区允许此内容与工具方式。
- 台账和页面没有相同动作、未决提交、拒绝或删除记录。
- 安装/保存/关闭页面等建议的风险明确，例如先保存未完成的编辑内容。

不虚构故事、亲身经历、用户数、客户、效果、优惠、背书和评价。不操纵评分、投票、点赞或伪装第三方推荐。

## 有副作用的操作顺序

1. 给动作稳定 `action_id`，写 `prepared` 记录；不能持久化时保留恢复摘要。
2. 再核对账号、对象、内容与许可，发送或提交一次。
3. 读取最新页面、API 回执或消息状态，查真实产物。
4. 记录实际状态、链接和证据，不凭点击或 HTTP 成功断言发布成功。
5. 不明确则记 `unknown`，先查目的地和已发送记录，查清前不重试。

保存稳定 permalink、消息或提交 ID。浏览器执行按工具要求保存并展示可核对截图，不泄露无关私信、凭据或个人信息。

## 状态

| 状态 | 已证明什么 |
|---|---|
| `draft` | 内容已准备，未提交 |
| `prepared` | 动作已登记，尚无发送证据 |
| `submitted` | 有提交/发送回执，不保证公开 |
| `visible_self` | 当前登录账号可见，未独立证明别人可见 |
| `public_verified` | 有可说明的独立可见性证据，不默认推断 |
| `pending_review` | 平台明确显示审核中 |
| `filtered` / `removed` | 有过滤或移除证据，不算有效曝光 |
| `unknown` | 副作用未确认，阻止盲目重试 |
| `blocked` | 缺账号、许可、预算、接口等明确前提 |
| `failed` | 已确认失败，记原因 |

回复、体验、激活、付费另记业务事件，不覆盖审核或可见性状态。草稿不能写成已执行。

## 失败和停止

- 身份不明：暂停相关写操作，继续无关准备。
- 过滤、删除、平台限制：不改写重发、切号或规避风控。询问管理员是另一项对外沟通，需在授权内。
- 费用/邀请码：说明成本，未批准不支付，给替代方法。
- 超时/按钮无反馈：先确认是否已提交，不循环重试。仅在已确认无副作用、错误可恢复且仍获授权时尝试一次修复，再失败即报告。
- 无匹配对象：报告零条合格机会和筛选原因，不凑数。
- 用户或对象拒绝、平台警告、许可到期：停止相关联系，保留防止重联的最小记录。

账号一次受限不等于渠道无效，一次成功不等于可规模化。

## 汇报格式

```text
实际完成：动作、账号、对象、内容摘要与链接
验证状态：提交 / 自己可见 / 公开核实 / 待审 / 过滤 / 未知
获得信号：真实回复和体验反馈；没有则写尚无
未完成：具体阻碍，不把草稿算执行
下一步：一个最有价值的动作或观察点
是否设计定时跟进：未拒绝且没有等价任务时再问
```
