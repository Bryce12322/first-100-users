# 渠道卡与动态核验

## 使用方式

这是候选入口和方法库，不是已认证的免费渠道清单。规则示例核对于 2026-10-19，执行时重查官方及具体社区规则；无法核实则标记未知，不能用旧日期代替当前检查。

对选用渠道补齐这些字段，再承诺可执行：

```text
渠道 / 具体入口 / 适用人群与阶段：
真实机会及来源 / 需求是否仍存在 / 产品是否匹配：
现金费用 / 准备时间 / 维护成本 / 反馈周期：
账号与语言门槛 / 当前账号身份：
参与、自推广、链接、AI 内容与自动化规则：
可用工具的读写能力 / 是否需用户接手：
最小动作 / 验证方式 / 停止条件：
规则来源 / 核验日期 / 未知项：
```

接口可用不等于平台批准，登录不等于授权，官网存在不等于免费收录。

## 社区与对话

### Reddit 与垂直论坛

- 适合：具体场景求助、主动试用邀请、允许分享产品的栏目。
- 路径：相关社区 → 读版规与原文/回复 → 判断需求 → 起草有用回应 → 按授权发布 → 保存评论链接和状态。
- 核查：新账号、链接、自推广、AI 内容限制；帖子的 flair 规则不能自动套用评论，反之亦然。必要时读社区 wiki。
- API 访问须有 Reddit 明确批准，商业数据用途须核实书面许可；应用/Agent 还需核对注册、标识和账号用途要求。用户同意推广不能替代这些平台前提，不因连接器已连通就跳过。
- 观测：有用回复、体验意愿、实际激活；不把评论自动点赞当用户。
- 停止：过滤、删除、拒绝、账号限制后不改写重发规避。不从竞品发布帖抢流量，不在健康等敏感场景利用脆弱性推销。
- 来源：[Reddit Spam](https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam)、[Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)，另查具体社区规则。

### X

- 适合：研究公开需求、发布真实场景演示、按当前许可参与交流。
- 核查：账号、发布工具合规性、自动回复与主动私信限制、接口费用。
- 已核对规则：禁止网站脚本式非 API 自动化；禁止仅凭关键词搜索发送自动陌生人回复。官方 API 可用或只发一条都不等于自动回复许可。
- 不开展关键词触发的陌生人自动回复活动。无法合规执行时交付原帖链接、需求判断与供用户亲自判断的草稿，准确报告未发送。
- 来源：[X Automation Rules](https://help.x.com/en/rules-and-policies/x-automation)。

### Discord、Slack、微信群、QQ群

- 适合：明确主题的群体、管理员允许的分享或反馈栏目。
- 最小动作：读群规，在合适频道分享一个有用工作流或回应明确求助。
- 核查：邀请、身份、成员资格；未获访问权限不抓私人群消息。
- 不自动大量入群或给成员群发私信。群链接、成员列表不等于联系许可，也不等于允许向外散布群内信息。
- 按具体群与平台当前规则核实。

### V2EX 与中文垂直论坛

- 适合：开发者和工具用户的问题、允许作品分享的节点。
- 核查：账号可否发言、激活/邀请/余额、节点和自动化规则。
- 最小动作：一个匹配节点的中文场景介绍或有用回复。
- 费用或邀请门槛未知不称免费，不擅自购买。
- 参考：[V2EX FAQ](https://www.v2ex.com/faq)，以当前页面和节点规则为准。

### Hacker News / Show HN

- 可评估技术受众与真人展示，不属于通用 AI 代发渠道。
- 已核对规则：不发布生成或 AI 编辑的文本，强调人与人的讨论。
- 只核对产品事实、整理用户可自行检查的资料和规则；不生成供发布的 HN 正文或评论，不代发。用户自行原创并决定是否参与。
- 来源：[HN Guidelines](https://news.ycombinator.com/newsguidelines.html)、[Show HN](https://news.ycombinator.com/showhn.html)。

## 内容、合作与邀请

### 小红书、B站、YouTube、个人博客

- 适合：真实前后差异、教程、可复现任务。
- 最小动作：一个问题、一段真实演示、一个行动入口；按受众选择图文或视频，不默认长视频。
- 核查：商业披露、外链、自动化、素材版权、制作费用。
- 不用合成素材伪装实测，不把观看量当激活。工具不可用则交付素材与步骤，不声称发布。

### 邮件、LinkedIn、定向私信

- 适合：相关性强、单位用户价值较高、可说明联系理由的对象。
- 最小动作：一个真实对象、一个已核实需求、一封个性化邀请；优先已有关系或明确接收相关联系的入口。
- 核查：联系方式来源、联系许可、适用规则、拒绝与退订记录。公开邮箱不等于营销订阅，未回复不等于同意追发。
- 不抓私人联系方式，不自动扩成名单，不虚构熟悉关系或主题行。

### 小创作者、垂直通讯、媒体

- 适合：作者受众与产品场景一致，或有可验证新闻点。
- 最小动作：一位作者、一段真实相关内容、一个适合其受众的试用方案。
- 核查：投稿方式、赞助披露、报价、素材授权。不保证免费合作，不要求好评。
- 发出邀约不等于合作达成，不连续催促未回复者。

### 互补产品、模板、开源与资源社区

- 适合：自然互补关系、独立有用的示例或模板。
- 最小动作：一个集成示例、可用模板或双向受益提议。
- GitHub issue、PR、讨论和资源列表仅在真实相关且维护者允许时参与。不留无关广告、不建空 PR、不假装用户推荐自己。
- 核实代码/素材许可和可用性，不擅自公开私有代码。

## 发布、发现与承接

### Product Hunt

- 适合：已有体验入口、定位清楚、具备演示素材的阶段性发布。
- 官方入口说明免费使用，但筹备、素材、账号和后续交流有时间成本；重查当前条件和排期。
- 最小动作：先完成一个发布草稿；草稿、已排期和已公开分开验证。
- 不买 hunter、刷流量、要求直接投票；按当前规则判断 Agent 可做哪些步骤。
- 来源：[Launch Guide](https://www.producthunt.com/launch)、[What to know before you launch](https://www.producthunt.com/launch/how-product-hunt-works)。

### 目录、工具集合、行业资源页

- 适合：受众匹配、审核和提交方式清晰的入口。
- 最小动作：核查一个目录的相关性、活跃程度、费用和链接规则，再提交一次。
- 大量低质目录不是 SEO 保证，不承诺排名、链接或曝光。付费收录、加速审核与订阅单独获准。

### Chrome Web Store 等应用市场

- 适合：改进自然发现与列表到安装的承接。
- 最小动作：核对标题、描述、首图、价格和权限表达，给一处有依据的改稿；写后台前核实权限与范围。
- 元数据修改、版本发布、权限改变是不同动作，不能相互授权。不刷评论、不奖励好评、不误导隐私。
- 来源：[Best Practices](https://developer.chrome.com/docs/webstore/best-practices)、[Discovery](https://developer.chrome.com/docs/webstore/discovery)。

### 搜索与长尾问题内容

- 适合：用户会主动搜索、有真实问题可回答的产品。
- 最小动作：核实一个搜索意图，给实践步骤和自然体验入口。
- 不保证即时流量；分开发布、索引、合格访问和激活。无授权不改站、不部署、不加分析脚本。
- 不批量生成薄内容或虚构竞品缺点；核实来源和功能。
- 来源：[Google Search Essentials](https://developers.google.com/search/docs/essentials)。

### 线下社区与场所

- 适合：本地服务、学校、职业圈或能现场完成体验的产品。
- 最小动作：一个获许可场所、一个演示任务、一个体验入口。
- 用户负责出席与实体操作，Agent 可准备材料或经批准联系。核查场地、印刷、交通、摄影许可与费用，不自行订购。

## 维护

只核验本轮所需渠道。政策/费用变化记录当前来源和日期；账号特有阻碍存到产品台账，不因单次失败修改所有人的公共方法库。公共规则仅保留有权威来源且可复用的部分。
