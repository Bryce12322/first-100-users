# 示例：为一个标签页工具选择下一轮行动

这是一次真实公开网页分析的编辑整理示例，用来展示输出形态，不是完整对话，也不是获客成功案例。

**资料读取日：2026-10-20。** 下面涉及页面状态和商店数据的内容都是当天快照；本示例编写时未重新确认它们是否仍然如此。若拿这个产品重新做行动，需要重新核实。

## 输入

```text
使用 $first-100-users 分析 https://trytabspace.com/，推荐下一轮最小获客行动。
```

## 读到了什么

| 证据类型 | 当时获得的信息 | 来源 |
|---|---|---|
| 页面已核实 | 官网仍称商店发布筹备中，主按钮指向帮助页 | [官网](https://trytabspace.com/) |
| 页面已核实 | Chrome 商店已有 JevtabAI 条目，显示 4 位用户、无评分，版本 0.8.0，更新时间为 2026-10-18 | [商店](https://chromewebstore.google.com/detail/okgbmkkonkhnmhpfehclhmmnmgninefk) |
| 官方描述，未实测 | 按 Space 和用户写的分类规则生成保存链接的分类建议，由用户审核应用 | [帮助页](https://trytabspace.com/help/) |
| 官方描述，未实测 | 有限次免费 AI 试用，之后需用户自己的供应商 API key；AI 会发送部分链接元数据和分类规则 | [帮助页](https://trytabspace.com/help/)、[隐私页](https://trytabspace.com/privacy/) |
| 未知 | 外部用户反馈、有效使用、重复使用、现有推广效果 | 公开页面不能证明 |

## 当时可以怎样建议

**在尚未取得现有反馈的条件下，先招募最多 3 位同时做多个研究项目的 Chrome 用户，观察他们能否完成保存、分类和次日找回。**

理由：公开商店数字不能说明用户是否获得价值；先验证写规则和审核建议的成本是否值得，再决定扩大曝光。官网与商店发布状态不一致，是这次动作的直接承接问题；可以先在招募材料里直接给商店链接，改站另行安排。

| 行动卡 | 内容 |
|---|---|
| 目标人群 | 同时做两个研究项目、经常把相关链接混放在同一窗口的人；这是待验证的人群假设 |
| 方法与候选位置 | 一次定向试用征集；当时核查的候选入口为 r/BetaTests，执行前须重查规则与账号条件 |
| 任务 | 用 10–20 个非敏感链接，创建两个项目 Space，保存、生成并审核建议；次日重新打开一个项目 |
| 一个问题 | 加上写规则和审核的时间，这是否比原来的整理方式更省事？ |
| 观察窗口 | 72 小时观察招募情况，最多跟进 3 位自愿者至第 7 天；没有回复也按零记录 |
| 完成口径 | 分开记录愿意尝试、实际完成、次日找回和之后再次使用，不把评论或安装当激活 |
| 成本边界 | 不新增广告或奖励；只在已确认可用的免费试用额度内测试 |
| 停止条件 | 被过滤或删除不改写重发；出现保存或恢复异常时暂停招募 |
| 执行状态 | 仅有分析与素材准备，没有发布或联系他人 |

只处理链接分类；不把它推荐给全文研究问答、提醒待办、保留未保存草稿等未证实需求。

## 这个示例还暴露了什么问题

现有反馈会改变首选动作，因此应尽早确认。如果使用者已说明“有使用反馈”，应优先读取这些证据，再判断要扩大某个渠道、降低首次使用门槛，还是解决重复使用。不能仍把“没有真实反馈”当成事实。

因此上面的招募建议是**条件化方案**，并非产品的最终增长诊断。v0.1.0 在技能中补强了这一点。

## 没有验证什么

没有安装或实测扩展，没有观察受试者，也没有已发送招募、公开曝光、激活或留存结果。这个示例说明的是如何把公开事实和未知项转成一个可验证的动作，不能作为增长效果宣传。
